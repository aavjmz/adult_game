## 🎮 游戏流程

### 1. 玩家登录流程
```
客户端 → 连接WebSocket服务器
      → 发送登录请求（玩家ID/Token）
      → 服务器验证身份
      → 返回玩家数据（卡组、等级、战绩）
      → 进入主界面
```

### 2. 匹配流程
```
客户端 → 点击"开始匹配"
      → 发送匹配请求（PVP/PVE，等级范围）
      → 服务器加入匹配队列
      → 找到对手或AI
      → 创建游戏房间
      → 双方进入房间
      → 开始游戏
```

### 3. 战斗流程
```
客户端 → 选择卡牌出牌
      → 发送操作到服务器
      → 服务器验证合法性
      → 执行战斗逻辑
      → 广播状态更新
      → 双方客户端同步渲染
      → 回合结束
      → 判断胜负
```

## 🔧 技术栈

### 后端
- **Flask**: Web框架
- **Flask-SocketIO**: WebSocket实时通信
- **SQLAlchemy**: ORM数据库管理
- **Redis**: 会话缓存、匹配队列
- **Celery**: 异步任务（可选）

### 前端
- **PixiJS**: 游戏渲染引擎
- **Socket.IO Client**: WebSocket客户端
- **GSAP**: 动画库
- **状态管理**: 简单的事件驱动模型

### 数据库
- **开发环境**: SQLite
- **生产环境**: PostgreSQL
- **缓存**: Redis

## 🔌 WebSocket 通信协议

### 客户端 → 服务器事件

```javascript
// 连接事件
connect: { player_id, token }

// 匹配事件
match_request: { mode: 'pvp'|'pve', rank_range: [min, max] }
cancel_match: {}

// 战斗事件
play_card: { card_id, target_id }
end_turn: {}
surrender: {}

// 聊天事件（可选）
send_message: { message }
```

### 服务器 → 客户端事件

```javascript
// 连接响应
connect_success: { player_data, cards }
connect_error: { error }

// 匹配响应
match_found: { room_id, opponent, battle_mode }
match_cancelled: {}

// 战斗状态
battle_start: { initial_state }
turn_start: { player_id }
card_played: { player_id, card, effects }
state_update: { game_state }
battle_end: { winner, rewards }

// 错误事件
error: { code, message }
```

## 🔒 安全考虑

1. **操作验证**: 服务器验证所有游戏操作的合法性
2. **防作弊**: 关键逻辑在服务器执行，客户端只负责展示
3. **Token认证**: WebSocket连接需要验证Token
4. **速率限制**: 限制操作频率，防止刷屏
5. **数据加密**: 敏感数据传输加密
